spelling-buddy

A procedural 2.5D character rig for Canvas2D and SVG. No image assets, no runtime dependencies — the character is math.

try it

Drag the character to turn it. Everything you see is drawn from about fifteen numbers — arcs, ellipses and Bézier curves evaluated per frame.

  • Infinite resolution. Identical at 24px in a toolbar and 2000px on a projector.
  • It deforms. Squash, stretch, head turns and expression blends are computed, so poses interpolate instead of snapping.
  • It turns. Features live on a sphere; profile views and full turnarounds come from the same nine expressions.
  • One rig, many outputs. The same drawing code renders live to Canvas2D and emits real SVG, PNG, sprite sheets and GIFs.

~35 kB minified · zero dependencies · MIT

Install

npm install spelling-buddy

No build step? Use the prebuilt bundle:

<script src="spelling-buddy/dist/spelling-buddy.global.js"></script>
<script>
  const { buddy } = SpellingBuddy.mount('#buddy')
</script>

sharp is an optional dependency used only by the PNG/GIF exporters. Skip it — the SVG exporter still works.

Expressions are states. Actions are events. Set an expression when your UI enters a mode; fire an action when something happens. That one distinction answers most integration questions.

Interruption is safe

The running action's end() is called before a new one starts, so orientation and hand state are always restored. Fire on every keystroke if you like — nothing accumulates.

buddy.react('nod')
buddy.react('correct')   // nod ends properly; correct starts clean

if (!buddy.busy) buddy.react('lookAround')   // or guard instead

Idle behaviour

mount('#buddy', { idleActions: true, idleEvery: [12, 25] })

Every 12–25 s of inactivity it plays a random idle-tagged action. Never fires while something else is running.

Head control

Independent of expression and actions.

yaw0°
pitch0°
buddy.face(45, -10)      // degrees: yaw, pitch. Turns off cursor tracking.
buddy.turnBy(0.2, 0)     // radians, relative — for drag gestures
buddy.s.autoLook = true  // hand control back to the cursor

Yaw is unbounded — pass 540 for one and a half turns. Pitch is clamped to about ±32°, past which the face leaves the silhouette.

Spelling

The domain-specific behaviour: hold up each letter in turn, then celebrate.

speed0.48s

events appear here

buddy.on('spell:letter', ch => speak(ch))
buddy.on('spell:done',   () => speak('That spells ' + word))

buddy.spell('CAT', { interval: 0.6 })   // slower for younger learners

spell() is driven by the rig's own clock, so it stays in sync at any timestep and exports frame-accurately. Non-letters are stripped.

Driving the mouth from TTS

const utter = new SpeechSynthesisUtterance(word)
buddy.attachSpeech(utter)     // mouth follows the audio
speechSynthesis.speak(utter)

The mouth articulates real shapes rather than flapping — see Speech & visemes. spell() already does this per letter; pass { speak: false } for cards only.

Speech & visemes

The character articulates — it forms actual mouth shapes for sounds rather than flapping open and shut. For a spelling app that's the difference between a mascot that reacts and one that teaches.

A viseme is numbers, not a drawing. { w, h, round, teeth, tongue, lift } — so any two blend continuously. The mouth travels through the shapes instead of cutting between them, which is what reads as speech rather than as a jaw hinge. A sprite sheet cannot do this.

Letter names are exact

buddy.sayLetters('CAT')   // "see" "ay" "tee"

Spelling apps say letter names, not letter sounds, and there are only 26 — so it's a lookup table, not a guess. C → ['etc','E'], B → ['MBP','E'].

Words are approximate

buddy.say('through')   // → L etc O
buddy.say('make')      // → MBP AI etc   (silent final e dropped)

Full grapheme-to-phoneme needs a pronunciation dictionary. Lip-sync doesn't — it needs plausible movement in the right rhythm, and nobody can tell a near-miss viseme from an exact one at speaking speed. The rules handle digraphs, vowel pairs, doubled consonants and silent e, and get the visually distinctive consonants right, which is where the eye looks.

Exact control, and real audio

buddy.sayVisemes([['MBP', 0.08], ['AI', 0.22], ['etc', 0.1]])

const utter = new SpeechSynthesisUtterance('cat')
buddy.attachSpeech(utter)          // mouth follows the audio
speechSynthesis.speak(utter)

attachSpeech uses boundary events. Where an engine doesn't emit them the mouth stays closed by design — a still mouth reads better than a wrong one.

While speech is active the viseme system owns the mouth; eyes and brows stay with the expression, so "speaking while proud" reads correctly.

Tracing & cues

The character steps aside and a letter draws itself — stroke by stroke, in the order and direction you'd write it, with the pencil visibly lifting between strokes.

trace
speed 2.40s
This was nearly free. The glyphs are monoline strokes, so their path data is already the pen's centreline — the same coordinates that draw an "A" describe how to write one. Tracing needed no new artwork; the alphabet just had to be sampled by arc length instead of stroked all at once. A filled-outline font can't do this: outlines describe the edge of the ink, not the path through it.

Lowercase and digits trace too, on real ruled paper: the cap line, the x-line and the baseline always, plus the descender rule for the letters that go below it. Without the x-line a lowercase o has nothing to sit against, and "short letters stop here" is not something the child can see.

buddy.trace('A', { duration: 2.4, hold: 0.7 })
buddy.trace('g')   // case is preserved — this is a lowercase g
buddy.on('trace:done', () => input.focus())

Duration is spread by arc length, so the pen moves at constant speed and a long stroke takes proportionally longer — which is what makes it read as handwriting rather than as a progress bar.

Reading the pen yourself

import { penAt, glyphPath } from 'spelling-buddy'

penAt('A', 0.5)    // → { x, y, stroke, into, penUp }
glyphPath('A')     // → { strokes: [{ pts, cum, len }], len }

Everything you need to score how closely a traced finger followed the path.

The rig makes no sound. It reports when something worth hearing happened, so you can attach audio without reverse-engineering animation timings.

Theming

No colour is hard-coded. Every fill reads from a theme object.

Brand System v4.1

canvas #FFFFFF ink · action green · feedback blue · selection cream · editorial

The default theme puts the body in ink — the character is the action colour. Blue carries the sparks. Green appears only on correct, never as decoration, which is what keeps it meaning "you got it right".

Build your own

generated
mount('#buddy', {
  theme: { extends: 'ink', body: '#0B2A4A', hand: '#082138', spark: '#FFC94A' }
})
The one rule: hand must differ visibly from body. Hands orbit just outside the silhouette but pass in front of it during turns. Painted the same colour they render perfectly and are invisible. This is the bug that cost the most time during development — the geometry was right for three iterations while nothing appeared on screen.

Asset export

Every asset comes out of the same rig that runs at runtime, so exported art can never drift from what ships.

npx spelling-buddy sheet                       # one SVG character sheet
npx spelling-buddy svg    --out assets/svg     # per-pose SVGs
npx spelling-buddy png    --size 512           # rasterised stills
npx spelling-buddy sprite --action correct     # sprite-sheet PNG
npx spelling-buddy gif    --action wave        # animated GIF

svg and sheet need nothing installed. png / sprite use sharp; gif also needs ffmpeg.

Determinism

Frames come from a seeded PRNG at a fixed timestep. Export twice, get byte-identical output — which makes generated assets safe to commit and to diff in CI:

- run: npx spelling-buddy svg --out assets/svg
- run: git diff --exit-code assets/    # fails if the rig changed the art

That check turns "someone tweaked the eye radius" from a thing you notice in production into a failing build.

The projection

The turn is real 3D, not sprite swapping. Each facial feature is given a position on the surface of a sphere; yaw and pitch rotate it, and an orthographic projection returns the 2D position and the local foreshortening.

yaw 42° cheated (used) true projection

Left: the sphere, with both feature positions drawn — filled marks are what the rig uses, hollow rings are the physically true projection. Past ~50° the true positions leave the silhouette entirely. Right: the rendered result.

function project(sx, sy, R, yaw, pitch) {
  const lon = Math.asin(sx / R) + yaw      // longitude after turning
  const lat = Math.asin(sy / R) + pitch    // latitude after tilting
  return {
    x:  R * Math.sin(lon) * Math.cos(lat),
    y:  R * Math.sin(lat),
    z:  R * Math.cos(lon) * Math.cos(lat), // >0 = near hemisphere
    fx: Math.cos(lon),                     // horizontal squeeze
    fy: Math.cos(lat),                     // vertical squeeze
  }
}

Expression code never sees an angle. It receives a frame of projected positions and scale factors, which is why a new expression costs nothing in projection logic and works at every head angle automatically.

The wrap cheat

A physically true projection slides features all the way out to the silhouette, where they overhang the body edge and look broken. Animators pull the travel inward; so does this rig.

const wrap = 1 - 0.45 * Math.abs(Math.sin(yaw))   // 45% pull-back at full profile

The important part is what doesn't get cheated. Foreshortening still comes from the real angle, so the squash stays physically correct. Only the translation is stylised.

Group anchoring

The first version applied the cheat per feature. That squeezed the eyes together on top of the genuine perspective compression, crowding them into a blob near profile. The fix: cheat only the face group's anchor point, then lay features out around it with the honest projection.

function faceProject(sx, sy, yaw, pitch) {
  const aW = project(0, faceCY, Rf, yaw, pitch, /* wrap */ true)
  const a0 = project(0, faceCY, Rf, yaw, pitch, /* wrap */ false)
  const q  = project(sx, sy,    Rf, yaw, pitch, /* wrap */ false)
  return { x: q.x + (aW.x - a0.x), y: q.y + (aW.y - a0.y), z: q.z, fx: q.fx, fy: q.fy }
}

Travel is stylised; internal spacing stays honest.

Springs, not tweens

Every impulse is injected as velocity into a damped spring rather than played as an eased keyframe.

function spring(pos, vel, target, dt, k = 190, d = 15) {
  vel += ((target - pos) * k - vel * d) * dt
  return [pos + vel * dt, vel]
}

Eased tweens arrive and stop. Springs overshoot and settle. That difference is most of what reads as weight.

compare ink = spring · blue = eased tween

Which gives actions two rules:

  • Never assign a position. Set a spring target (yawTarget) or inject velocity (offVY, squashVY).
  • Restore whatever you changed in end().

That's why interrupting mid-flight never leaves a broken pose, and why hand-authored beats and physical settling don't fight.

Adding an action

import { ACTIONS } from 'spelling-buddy'

ACTIONS.bounceTwice = {
  dur: 1.2,
  tags: ['physical'],
  start(B) { B.express('excited'); B.s.offVY = -180 },
  tick(B, p) { B.once(0.5, () => { B.s.offVY = -140 }, p) },
  end(B) { B.express('happy') },
}

Anything you add appears at runtime, in Buddy.actions, and in every exported asset.

Surface backends

The rig never touches a CanvasRenderingContext2D. It draws against a narrow interface:

save restore translate rotate scale alpha
begin move line quad cubic arc ellipse rect close
fill stroke clip text clear

CanvasSurface forwards those to Canvas2D. SVGSurface accumulates path data, converting arcs to cubic Béziers and baking transforms as matrices. Neither knows anything about the character.

Two deliberate differences from raw Canvas2D:

  • fill(color) takes paint as an argument instead of reading mutable fillStyle. Stateless paint makes the SVG backend trivial and removes a class of "forgot to reset the style" bugs.
  • alpha(x) multiplies rather than assigns, so nested groups compose.

The payoff: add an expression once and it appears at runtime, in exported SVG, in the sprite sheet, and in the GIF.

The clipping subtlety

Worth knowing if you extend the SVG backend. Shapes carry their absolute CTM as a transform, and SVG resolves clip-path in the user space established after that transform. Putting clip-path on the shape itself applies the matrix twice and clips everything away — which is exactly the bug that made every exported face come out empty.

The fix: clipping opens a plain untransformed <g> in root space, and the clipPath geometry carries the absolute matrix. Both then live in the same coordinate system, and nesting groups gives intersection semantics identical to canvas.

Troubleshooting

The hands never appear

Almost always colour, not geometry. Hands orbit just outside the silhouette but pass in front of the body during turns. If theme.hand equals theme.body they render perfectly and are invisible. Use one step off.

Second possibility: hands are opt-in. showHands defaults to false and animations request them per-frame — setting lift alone does nothing without want.

Nothing renders / blank canvas

The canvas has no CSS size — mount() measures the element, and one with no layout size measures 0. Set width/height in CSS or pass size. Also check you mounted after the element was in the DOM, and that you haven't disposed the handle.

The character is blurry

mount() handles device-pixel-ratio. If you drive your own loop you must scale the backing store yourself — unit = cssSize / 320, then ctx.setTransform(unit * dpr, 0, 0, unit * dpr, w / 2, h / 2).

Two buddies blink in unison

They share the default seed. Pass { seed: i } per instance. Identical seeds make a row of clones, which reads as wrong immediately.

A custom action leaves the rig in a broken pose

You assigned positions instead of targets, or skipped end(). B.s.yaw = 1.2 fights the spring every frame; set B.s.yawTarget instead and restore it in end(), because react() calls end() when interrupting.

Custom expression looks flat in profile

You're drawing at absolute coordinates instead of using the frame. Translate to F.eyeL.x/y and scale by F.eyeL.fx/fy. Guard fx with a floor — it reaches 0 at exact profile and a zero scale collapses the path.

It feels stiff, or too busy

Stiff: bobAmt/breathAmt at 0, blinkEvery too high (blinking is most of what reads as alive), or everything is express() and nothing is react().

Busy: idleActions on during focused input, firing correct per keystroke, or using dance for ordinary successes — save it for streaks.

Reduced motion

mount() reads prefers-reduced-motion and damps the idle oscillators automatically, following live changes to the setting. Opt out with { respectReducedMotion: false }.

Expressions and pose changes are left alone — they're state, not movement. Consider swapping big actions for small ones too (nod instead of correct).

Accessibility. The canvas is decorative — mark it aria-hidden="true" and put the real feedback in a live region. Never let the character be the only signal; colour and motion both fail for some users.
